# Telegram Ads Parser CRM

Локальная веб-CRM: собирает объявления услуг экспертов из открытых Telegram-каналов,
фильтрует двухступенчато и складывает карточки в общую Google-таблицу. См. полное ТЗ
в `TZ_telegram_parser_CRM.md` (в задаче/вложении).

## Стек

- Backend: Python 3.9 + FastAPI, SQLite (состояние чатов/позиций/прогонов)
- Парсинг Telegram: Telethon — твой личный аккаунт, официальный MTProto API
  (api_id/api_hash с my.telegram.org), только чтение истории публичных каналов
  без вступления в них
- Классификация/извлечение: Anthropic API, модель Claude Haiku
- Хранение карточек: Google Sheets (gspread + service account)
- Frontend: один статический HTML-файл (без сборки)

## Установка

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `backend/.env`:

1. **Telegram** — зарегистрируй приложение на https://my.telegram.org → `TELEGRAM_API_ID`,
   `TELEGRAM_API_HASH`, свой номер в `TELEGRAM_PHONE`.
2. **Anthropic** — `ANTHROPIC_API_KEY`.
3. **Google Sheets** — создай сервисный аккаунт в Google Cloud Console, скачай его JSON-ключ
   в `backend/data/google_service_account.json` (путь можно поменять в `.env`), включи Google
   Sheets API, дай сервисному аккаунту доступ редактора к таблице, впиши `GOOGLE_SHEET_ID`
   (из URL таблицы).

Разовый вход в Telegram (создаёт локальную сессию, спросит код из Telegram):

```bash
python login_telegram.py
```

Запуск сервера:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открой http://127.0.0.1:8000 — добавь чаты, жми «Старт».

## Бот @CariOra_bot (ввод + поиск по категории)

Отдельный процесс, работает с той же Google-таблицей карточек.

1. Токен — в @BotFather → выбери бота → API Token → впиши в `backend/.env` как `TELEGRAM_BOT_TOKEN`.
2. Запуск (в отдельном терминале, параллельно с сервером CRM):

```bash
cd backend
source .venv/bin/activate
python bot_main.py
```

Сейчас без модерации — то, что вносят через бота, сразу попадает в таблицу, как и собранное скрапером.

## Как это работает (кратко, по ТЗ)

- Кнопка «Старт» запускает один проход: собирает ровно 50 новых карточек, начиная с
  сохранённой позиции по чатам, переходя к следующему чату, если текущий закончился
  (пройдена глубина 6 месяцев) раньше, чем набралось 50.
- Ступень 1 (бесплатно): ключевые слова + признаки контактов в тексте — отсекает явный мусор.
- Ступень 2: один вызов Claude Haiku — классифицирует и сразу извлекает поля карточки.
- Дедуп: карточки с одинаковым (ник + нормализованный текст) не дублируются в таблице —
  в ТЗ это не описано явно, добавлено как разумное предположение.
- Позиция и статус каждого чата (`не начат`/`в процессе`/`пройден полностью`) хранятся
  в `backend/data/app.db` (SQLite) и переживают перезапуск.

## Известные допущения (см. также ответ в чате с разбором ТЗ)

- Глубина «6 месяцев» — приближённо 180 дней, без точной календарной арифметики.
- Ступень 1 — совпадение ИЛИ по ключевым словам ИЛИ по признаку контакта (не оба сразу),
  чтобы не терять реальные объявления до вызова модели.
- Оригинальный текст берётся из сырого поля Telegram-сообщения (без markdown-рендеринга),
  модель его не переписывает.
